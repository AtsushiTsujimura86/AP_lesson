## 01. 基礎理論・アルゴリズム・統計

**既存ノートから整理した項目**

### 逆ポーランド記法とスタック
逆ポーランド記法 = 演算子を数字の後ろに書く記法。

通常：

`(3 + 4) × 2`

逆ポーランド記法：

`3 4 + 2 *`

スタックを使うと簡単に計算できる。

1. 数字が来たらスタックにPUSH
2. 演算子が来たら必要な数だけPOP
3. 計算する
4. 結果を再びPUSH

例：

```text
3 → PUSH     [3]
4 → PUSH     [3, 4]
+ → 3+4      [7]
2 → PUSH     [7, 2]
* → 7×2      [14]
```

→ 最後にスタックに残った `14` が答え。

覚え方：  
**数字は積む、演算子が来たら取り出して計算する。**

### ベイズの定理
条件付き確率の向きを変えるために使う。

`P(A|B)` = Bであることが分かっている中で、Aである確率。  
`P(A∩B)` = 全体の中で、AかつBである確率。

`P(A|B) = P(A∩B) / P(B)`

また、

`P(A∩B) = P(B|A) × P(A)`

なので、

`P(A|B) = P(B|A) × P(A) / P(B)`

### 迷惑メールの例
学習時：

`P(FREEあり | 迷惑メール)`

→ 迷惑メールにはFREEという特徴がどれくらい出るか。

実運用時：

`P(迷惑メール | FREEあり)`

→ FREEという特徴を持つメールが、迷惑メールである確率。

つまり、  
**学習しやすい「特徴 | 判定結果」から、実際に知りたい「判定結果 | 特徴」を求める。**

### 正規分布
平均を中心とした左右対称の釣鐘型の分布。

- μ（ミュー） = 平均
- σ（シグマ） = 標準偏差  
  → データのばらつき具合

正規分布では、おおよそ、

- `平均 ± 1σ` の範囲 → 約68%
- `平均 ± 2σ` の範囲 → 約95%
- `平均 ± 3σ` の範囲 → 約99.7%

のデータが入る。

覚え方：

**1σ = 68%  
2σ = 95%  
3σ = 99.7%**

σが大きいほど、データが広くばらついている。

### M/M/1 待ち行列モデル
1つの窓口・サーバに、ランダムに要求が到着し、ランダムな処理時間で1件ずつ処理するモデル。

- λ（ラムダ） = 平均到着率  
  → 単位時間あたり何件来るか
- μ（ミュー） = 平均サービス率  
  → 単位時間あたり何件処理できるか
- ρ（ロー） = 利用率

`ρ = λ / μ`

例：

毎秒4件到着し、毎秒5件処理できる場合、

`ρ = 4 / 5 = 0.8`

→ サーバ利用率80%。

### 1 - ρ
`1 - ρ` は、サーバの余裕。

例：

`ρ = 0.8`

なら、

`1 - ρ = 0.2`

→ 20%の余裕がある。

利用率ρが1に近づくほど、サーバの余裕がなくなり、待ち時間が急激に増える。

### 平均サービス時間
1件を処理する平均時間。

`平均サービス時間 = 1 / μ`

例：

毎秒5件処理できるなら、

`1 / 5 = 0.2秒`

### 平均待ち時間
処理を開始するまでの平均待ち時間。

`平均待ち時間 = ρ / (1 - ρ) × 平均サービス時間`

`ρ / (1 - ρ)` は、  
**混み具合 ÷ サーバの余裕**  
というイメージ。

また、M/M/1では到着した要求から見ると、

`ρ / (1 - ρ)`

は平均的に自分より前に存在する処理数のイメージとして考えられる。

例：

`ρ = 0.8`

なら、

`0.8 / 0.2 = 4`

平均サービス時間が0.2秒なら、

`4 × 0.2 = 0.8秒`

待つ。

### 平均応答時間
待ち時間だけでなく、自分自身の処理時間まで含めた時間。

`平均応答時間 = 平均待ち時間 + 平均サービス時間`

または、

`平均応答時間 = 1 / (μ - λ)`

### 重要
`λ < μ`

でなければならない。

到着速度が処理速度以上になると、待ち行列が増え続ける。

覚え方：

**ρ = サーバの忙しさ**  
**1 - ρ = サーバの余裕**  
**ρが1に近づくと待ち時間が爆発する**

### アムダールの法則
システムの一部分だけを高速化しても、全体の高速化には限界があるという法則。

高速化率をS、並列化できる割合をP、並列数をNとすると、

`S = 1 / {(1 - P) + P / N}`

→ 高速化するなら、処理時間の大部分を占める部分を改善することが重要。

### ROC曲線
- **ROC = Receiver Operating Characteristic（受信者動作特性）**：二値分類で、判定のしきい値を変えたときの性能を表す曲線。
- **横軸：偽陽性率（FPR = False Positive Rate）**、**縦軸：真陽性率（TPR = True Positive Rate、再現率）**。
- **左上に近いほど良い**。**AUC = Area Under the Curve（曲線下面積）**は一般に1に近いほど識別性能が高い（0.5はランダム判定程度）。
- **覚え方**：**横＝誤報、縦＝見つける力。誤報が少なく、よく見つける「左上」が理想。**
- **例**：不正アクセス検知のしきい値を変え、見逃しと誤検知のバランスを確認する。

### 主成分分析（PCA）
- **PCA = Principal Component Analysis（主成分分析）**：多数の数値データを、情報（ばらつき）をできるだけ保ちながら**少数の新しい軸**にまとめる次元削減手法。
- **覚え方**：**たくさんの項目 → 特徴をよく表す少数の軸**。
- **例**：5教科の点数から「総合的な得点傾向」などを表す主成分を抽出する。
- ※正解ラベルを予測する手法ではなく、主にデータの構造を要約する手法。

### ハッシュ表と衝突
- **意味**：キーからハッシュ値を計算して保存先を決める。同じ場所になる**衝突**が起こり得る。
- **覚え方**：**住所を計算して素早く探すが、住所がかぶることもある**。
- **例**：衝突はチェイン法（リストで管理）やオープンアドレス法で処理する。

### ビットマスクと論理演算
- **意味**：ANDは必要なビットの抽出、ORはビットの設定、XORはビット反転に使える。
- **覚え方**：**AND＝残す、OR＝立てる、XOR＝切り替える**。
- **例**：`10110110 AND 00001111 = 00000110`（下位4ビットだけ抽出）。

### 混同行列・適合率・再現率
- **意味**：**適合率（Precision）＝TP/(TP+FP)**、**再現率（Recall）＝TP/(TP+FN)**。TPは真陽性、FPは偽陽性、FNは偽陰性。
- **覚え方**：**適合率＝陽性と言った中で正解した割合、再現率＝本当の陽性を拾えた割合**。
- **例**：迷惑メールを10件と判定し8件が正解→適合率80%。本当の迷惑メール20件中8件を検知→再現率40%。

## 02. コンピュータ構成・OS・ハードウェア

**既存ノートから整理した項目**

### DSP
Digital Signal Processor、デジタル信号処理のためのプロセッサ  
- 積和計算が得意
- 信号処理
- デジタルフィルタ

### メモリインタリーブ
主記憶を複数のバンクに分け、並行してアクセスすることで高速化する方式。  
1つのメモリへのアクセス完了を待つ間に、別のバンクへアクセスできる。

### DMA
DMA = Direct Memory Access（直接メモリアクセス）  
CPUを介さず、入出力装置と主記憶の間で直接データ転送する方式。  
→ CPUの負担を減らせる。

### ユニファイドメモリ
CPUとGPUなどが同じメモリ空間を共有する仕組み。  
CPU用・GPU用にデータをコピーする必要を減らせる。

### ウェアレベリング
フラッシュメモリの特定領域だけに書込みが集中しないよう、書込み場所を分散させる技術。  
→ SSDなどの寿命を延ばす。

### プリエンプション
Preemption = 先取り、取り上げること。  
OSが実行中のプロセスからCPU使用権を一時的に取り上げ、別のプロセスへ割り当てること。

### ラウンドロビン
各プロセスに一定時間ずつCPUを順番に割り当てるスケジューリング方式。  
時間切れになるとプリエンプションして次のプロセスへ移る。

### リエントラント
Reentrant = 再入可能。  
あるプログラムの実行途中でも、別の処理から同じプログラムを安全に呼び出せる性質。  
複数の処理から同時に利用しても問題が起こらないように作られている。


### キャッシュメモリとヒット率
- **意味**：CPUと主記憶の速度差を埋める高速メモリ。ヒット率が高いほど平均アクセス時間が短くなる。
- **覚え方**：**よく使うものを机の上に置く**。
- **例**：ヒット時間1ns、ミス時100ns、ヒット率90%なら単純モデルの平均は`1×0.9+100×0.1=10.9ns`。

### TLB（アドレス変換キャッシュ）
- **意味**：**TLB = Translation Lookaside Buffer**。仮想アドレスから物理アドレスへの変換結果を保持する。
- **覚え方**：**ページ表の近道**。
- **例**：TLBに変換結果があれば、ページ表を調べる手間を減らせる。


### ミューテックスとセマフォ
- **意味**：ミューテックスは排他ロック、セマフォはカウンタで同時利用数などを制御する同期機構。
- **覚え方**：**ミューテックス＝1人用の鍵、セマフォ＝利用可能な席数**。
- **例**：共有変数の更新はミューテックス、接続数を最大3に制限するなら計数セマフォ。


### RAID 0・1・5・6
- **意味**：RAID 0＝ストライピング（冗長性なし）、1＝ミラーリング、5＝分散パリティ（1台故障耐性）、6＝二重パリティ（2台故障耐性）。
- **覚え方**：**0＝速いが守らない、1＝丸ごと複製、5＝1台、6＝2台まで**。
- **例**：3台の同容量ディスクのRAID 5は、利用可能容量が約2台分。

## 03. システム構成・クラウド・信頼性

**既存ノートから整理した項目**

### フォールトトレランス
Fault Tolerance = 障害許容性。  
一部に故障が発生しても、システム全体として処理を継続できるようにする考え方。  
例：RAID5

### フェールソフト
Fail Soft  
障害発生時にシステム全体を停止させず、機能や性能を落としながら処理を継続する考え方。

### ハイパーバイザー型
Hypervisor = 仮想マシンを管理する仕組み。  
1台の物理マシン上で複数のOSを動作させる。

物理ハードウェア  
↓  
ハイパーバイザー  
↓  
OS A / OS B / OS C

各仮想マシンは基本的に独自のOS・カーネルを持つ。

### コンテナ型
1つのOSのカーネルを複数のコンテナで共有し、アプリケーションの実行環境だけを分離する方式。  
仮想マシンより軽量で起動が速い。

### カーネル
Kernel = OSの中核部分。  
CPU、メモリ、プロセス、入出力装置などのハードウェア資源を管理する。

コンテナ型では、コンテナごとに完全なOS・カーネルを持たず、ホストOSのカーネルを共有する。

### オブジェクトストレージ
データを「オブジェクト」という単位で管理するストレージ。

オブジェクト =
- データ本体
- メタデータ
- 一意なID

### メタデータ
「データについてのデータ」。  
例：作成日時、所有者、ファイル形式、サイズ、タグなど。

### 増分バックアップと差分バックアップ

### 増分バックアップ

前回のバックアップから変更されたデータだけを保存する。

* バックアップ容量が小さい
* バックアップ時間が短い
* 復旧にはフルバックアップと、その後の増分バックアップが必要

### 差分バックアップ

最後のフルバックアップから変更されたデータをすべて保存する。

* バックアップ容量が大きくなりやすい
* 復旧が比較的簡単
* 復旧にはフルバックアップと最新の差分バックアップが必要

```text
日曜：フルバックアップ

        月曜      火曜         水曜
増分：  月        火           水
差分：  月        月＋火       月＋火＋水
```

覚え方：

**増分＝直前との差
差分＝最後のフルとの差**

### プロビジョニングツール

Provisioning = 必要な資源や環境を準備すること。

サーバやOS、ミドルウェアなどの環境構築・設定を自動化するツール。

例：

* Ansible：サーバの設定を自動化
* Terraform：クラウド上のインフラ構築を自動化

目的：作業の効率化、設定ミスの削減。


### 稼働率（直列と並列）
- **意味**：独立した機器の稼働率がa、bなら、**直列＝a×b**、両方が停止したときだけ全体停止する**並列＝1-(1-a)(1-b)**。
- **覚え方**：**直列＝全部動け、並列＝どれか動け**。
- **例**：それぞれ90%なら直列81%、並列99%。※独立故障などが前提。


### IaaS・PaaS・SaaS
- **意味**：IaaS = Infrastructure as a Service（基盤）、PaaS = Platform as a Service（実行環境）、SaaS = Software as a Service（完成アプリ）。
- **覚え方**：**I＝機械を借りる、P＝開発の土台を借りる、S＝ソフトを使う**。
- **例**：仮想サーバ／アプリ実行プラットフォーム／Webメール。

### スケールアップとスケールアウト
- **意味**：スケールアップ＝1台を高性能化。スケールアウト＝サーバの台数を増やす。
- **覚え方**：**アップ＝太くする、アウト＝横に増やす**。
- **例**：CPU増強がアップ、Webサーバを2台から4台に増設するのがアウト。

## 04. ネットワーク

**既存ノートから整理した項目**

### ネットワーク層とトランスポート層

### ネットワーク層（第3層）

相手のコンピュータまでデータを届ける。

* IPアドレスで宛先を指定
* ルータによる経路選択

IP = Internet Protocol（インターネットプロトコル）

### トランスポート層（第4層）

相手のコンピュータ内のアプリケーションにデータを届ける。

* ポート番号で通信先を識別
* TCPでは再送制御や順序制御を行う

TCP = Transmission Control Protocol（伝送制御プロトコル）

UDP = User Datagram Protocol（ユーザデータグラムプロトコル）

* TCP：再送や順序制御などを備える
* UDP：基本的に再送や順序制御を行わない

覚え方：

**IPアドレス＝建物の住所
ポート番号＝建物内の部屋番号**

### IPv4アドレスのクラス
- **IPv4 = Internet Protocol version 4**。従来の**クラスフルアドレス方式**では、先頭の8ビット（第1オクテット）で分類する。

| クラス | 第1オクテット | 標準サブネットマスク | 主な用途 |
|---|---:|---|---|
| A | 1～126 | 255.0.0.0（/8） | 大規模ネットワーク |
| B | 128～191 | 255.255.0.0（/16） | 中規模ネットワーク |
| C | 192～223 | 255.255.255.0（/24） | 小規模ネットワーク |
| D | 224～239 | なし | マルチキャスト |
| E | 240～255 | なし | 予約・実験用途など |

- **例外**：`127.0.0.0/8`はループバック用、先頭が0の範囲も通常のクラスAホストアドレスとして使わない。
- **覚え方**：**A＝1、B＝128、C＝192、D＝224、E＝240から**。A/B/Cはマスクが **/8 → /16 → /24**。
- **例**：`192.168.1.10`はクラスCに該当。
- ※現在のIPアドレス割当ては**CIDR（Classless Inter-Domain Routing：クラスレスな経路制御・アドレス表記）**が基本で、クラス分類は試験用の基礎知識。

### NTPがUDPを使う理由
- **NTP = Network Time Protocol（ネットワーク時刻同期プロトコル）**：ネットワーク上で時刻を合わせる。通常**UDP = User Datagram Protocol**の**123番ポート**を使用。
- **理由**：接続確立の手間が小さく、時刻の問い合わせを繰り返せる。古い時刻情報を再送することは有益でない場合がある。
- **覚え方**：**時刻は「確実に古い情報を届ける」より「新しい情報を軽く交換する」**。
- **例**：PCが時刻サーバに定期的に問い合わせ、時計のずれを補正する。


### CIDRとサブネット計算
- **意味**：**CIDR = Classless Inter-Domain Routing**。`/24`はネットワーク部24ビット、ホスト部8ビット。
- **覚え方**：**/の後＝ネットワーク部のビット数**。
- **例**：`192.168.1.0/26`のアドレス数は`2^(32-26)=64`、一般的な利用可能ホスト数は62。

### NATとNAPT
- **意味**：**NAT = Network Address Translation**はグローバルIPをプライベートIPアドレスに変換、**NAPT = Network Address Port Translation**はIPアドレスとポートを変換。
- **覚え方**：**NAPTのPはPort**。
- **例**：家庭内の複数PCが1つのグローバルIPv4アドレスを共有して通信する。

### ARPとMACアドレス
- **意味**：**ARP = Address Resolution Protocol**。IPv4の同一リンク上で、宛先IPv4アドレスに対応するMACアドレスを調べる。
- **覚え方**：**IPアドレスからLAN内の機器アドレスを調べる**。
- **例**：同一LAN内で送信前にARP要求をブロードキャストする。

### DHCP
- **意味**：**DHCP = Dynamic Host Configuration Protocol**。端末にIPアドレスなどのネットワーク設定を自動配布。
- **覚え方**：**IPアドレスの自動配布係**。
- **例**：Wi-Fi接続時にIPアドレス・DNSサーバなどの情報を取得する。

### DNSのA・AAAA・MX・CNAMEレコード
- **意味**：**DNS = Domain Name System**。A＝IPv4、AAAA＝IPv6、MX＝メール配送先、CNAME＝別名。
- **覚え方**：**AはIPv4、Aが4つでIPv6、MXはMail、CNAMEは別名**。
- **例**：メール配送先を調べるときはMXレコードを使う。

### TCPの3ウェイハンドシェイク
- **意味**：**TCP = Transmission Control Protocol**。接続確立時にSYN → SYN/ACK → ACKを交換する。
- **覚え方**：**つなぎたい→いいよ→了解**。
- **例**：TCP接続を確立してからHTTP/1.1のリクエストを送る。

### ICMPとping
- **意味**：**ICMP = Internet Control Message Protocol**。IP通信のエラー通知や診断に使う。
- **覚え方**：**ICMP＝ネットワークからのお知らせ**。
- **例**：`ping`では通常ICMP Echo Request/Replyを利用する。

### VLAN
- **意味**：**VLAN = Virtual Local Area Network（仮想LAN）**。物理的に同じスイッチでも論理的にLANを分割する。
- **覚え方**：**同じ建物内に、仮想的な別の教室を作る**。
- **例**：社内ネットワークを開発部門用・経理部門用に分離する。

### IPv6の基本
- **意味**：IPv6は128ビットのIPアドレスを使用。IPv4は32ビット。IPv6にはIPv4のようなブロードキャストはない。
- **覚え方**：**v4＝32ビット、v6＝128ビット**。
- **例**：IPv6では近隣探索にNDP（Neighbor Discovery Protocol）を使う。

### 代表的なポート番号
- **意味**：サービスを識別する番号。**HTTP 80/TCP、HTTPS 443/TCP（HTTP/3はUDP）、DNS 53/UDP・TCP、SSH 22/TCP、SMTP 25/TCP、NTP 123/UDP**。
- **覚え方**：**Web＝80/443、DNS＝53、SSH＝22、メール＝25、時刻＝123**。
- **例**：HTTPS用に443/TCPを許可するファイアウォール設定を行う。

## 05. データベース

**既存ノートから整理した項目**

### キー（データベース）
- 候補キー：主キーの候補。行を一意に特定できる最小セット
- 主キー：候補キーの代表
- 外部キー：ほかのテーブルの候補キーの参照

### SQL句
SELECT：取り出す
FROM：どの表から
WHERE：条件
GROUP BY：グループ化
HAVING：グループ化後の条件
ORDER BY：並べ替え
JOIN：表を結合
INSERT：追加
UPDATE：更新
DELETE：削除
CREATE TABLE：表を作る
PRIMARY KEY：主キー
FOREIGN KEY：外部キー
UNIQUE：重複禁止
NOT NULL：NULL禁止
ON DELETE CASCADE：親削除 → 子も削除
ON DELETE RESTRICT：子が参照中なら親削除を拒否

### SQLのGRANT文
- **GRANT**：データベース利用者などへ**権限を与える**SQL文。**REVOKE**：与えた権限を取り消す。
- **覚え方**：**GRANT＝与える、REVOKE＝取り消す**。
- **例**：`GRANT SELECT ON sales TO user1;` → user1にsales表の参照権限を与える。

### WHEREとHAVINGの違い
WHERE：グループ化する前の各行に対する条件  
HAVING：GROUP BYでグループ化した後のグループに対する条件

覚え方：

**WHERE = 行を絞る  
HAVING = グループを絞る**

### COUNT(*)とCOUNT(列名)の違い
COUNT(*)：行数を数える。NULLが含まれる行も数える。  
COUNT(列名)：指定した列がNULLではない行だけ数える。

### スタースキーマ
中心にファクトテーブル、その周辺にディメンションテーブル。  
分析したい実績データ、分析軸（商品名、店舗名など）

### ロールバック、ロールフォワード
- ロールバック：トランザクションを取り消す、やりかけのトランザクションを無かったことにする。
- ロールフォワード：障害が起こったときに、障がい前の状態に一度戻し、再度処理を行う。
違いは、結果的に進んでいる(forward)か戻っている(back)だけか。

### NoSQL
NoSQL = Not Only SQL  
関係データベース以外の方式も含むデータベースの総称。

大量データや、形が一定ではないデータを柔軟に扱いやすい。

### キー・バリュー型
Key-Value型。  
キーと値を1対1で保存する。

### ドキュメント型
JSONなどのドキュメント単位でデータを保存する。  
項目構造が多少違うデータも扱いやすい。

### ワイドカラム型
行ごとに異なる列を柔軟に持てる方式。  
大量データの分散処理に向く。

### グラフ型
データをノードと、その関係で表現する。

- ノード：人、商品など
- エッジ / リレーション：友人、購入した、所属するなど
- プロパティ：各ノードや関係が持つ情報

### BASE特性
BASEはNoSQLなどの分散データベースで重視される考え方。可用性優先。

- BA = Basically Available  
  → 基本的に利用可能
- S = Soft State  
  → 一時的なデータ不一致などを許容
- E = Eventual Consistency  
  → 最終的にはデータが一致すればよい

### CAP定理
分散システムに関する3つの性質。

- C = Consistency（一貫性）
- A = Availability（可用性）
- P = Partition Tolerance（ネットワーク分断耐性）

ネットワーク分断が発生した場合、CとAを同時に完全には満たせない。

### CP
Consistency + Partition Tolerance  
→ 一貫性を優先。

### AP
Availability + Partition Tolerance  
→ 可用性を優先。

覚え方：

**分断（P）が起きたら、一貫性（C）か可用性（A）のどちらを優先するかを選ぶ。**


### ACID特性
- **意味**：**Atomicity（原子性）・Consistency（一貫性）・Isolation（独立性）・Durability（永続性）**。トランザクションの信頼性を支える。
- **覚え方**：**全部かゼロ／整合性／互いに干渉しない／確定後は残る**。
- **例**：振込処理は出金と入金をまとめて成功または取消しにする（原子性）。

### 第1～第3正規形
- **意味**：第1＝繰返し項目をなくし、各値を原子的にする。第2＝非キー属性の候補キーの一部への関数従属をなくす。第3＝非キー属性の候補キーへの推移的関数従属をなくす。
- **覚え方**：**1＝繰返し禁止、2＝キーの一部だけに依存しない、3＝非キーを経由して依存しない**。
- **例**：社員表に部署名を繰り返し持つ代わりに、部署IDから参照する部署表を分ける。

### 内部結合と外部結合
- **意味**：**INNER JOIN（内部結合）**は一致した行だけ、**LEFT OUTER JOIN（左外部結合）**は左表の不一致行も残す。
- **覚え方**：**INNER＝共通部分、LEFT＝左側を全部残す**。
- **例**：注文がない顧客も一覧に出したい場合、顧客表を左側にLEFT JOINする。

### インデックスとB+木
- **意味**：インデックスは検索を速くする索引。DBではB+木などの構造が利用される。
- **覚え方**：**本の索引を使えば全ページを読まなくてよい**。
- **例**：顧客ID検索は高速化しやすい一方、索引が多いと更新コストが増える。

### 分離レベルとダーティリード
- **意味**：ダーティリード＝他トランザクションが**コミットしていない変更**を読んでしまうこと。
- **覚え方**：**未確定の答案を見てしまう**。
- **例**：取引Aが残高を一時的に変更し、確定前に取引Bがその値を読む。

### 悲観的ロックと楽観的ロック
- **意味**：悲観的＝競合を想定して事前にロック。楽観的＝更新時にバージョンなどを検査して競合を検出。
- **覚え方**：**悲観＝先に鍵、楽観＝最後に照合**。
- **例**：更新が多いデータは悲観的ロック、競合が少ないデータは楽観的ロックが候補。

### ER図
- **意味**：**ER = Entity-Relationship（実体・関連）**。データの実体と実体間の関係を表す。
- **覚え方**：**データベースの登場人物と関係図**。
- **例**：「顧客1人が注文を複数持つ」は顧客1：注文多の関連。

### SQLのDISTINCTとNULL
- **意味**：`DISTINCT`は検索結果の重複を除く。`NULL`は不明・存在しない値で、`= NULL`ではなく`IS NULL`で判定する。
- **覚え方**：**DISTINCT＝重複なし、NULLは＝で比較しない**。
- **例**：`SELECT DISTINCT dept FROM staff;`、`WHERE manager_id IS NULL`。

## 06. 情報セキュリティ・暗号・認証


### 情報セキュリティの7つの特性

### CIA（最重要の3要素）

* **C：Confidentiality（機密性）**
  許可された人だけが情報にアクセスできる。
  例：暗号化、アクセス制御

* **I：Integrity（完全性）**
  情報が正確で、不正に改ざんされていない。
  例：ハッシュ値、電子署名

* **A：Availability（可用性）**
  必要なときにシステムや情報を利用できる。
  例：冗長化、バックアップ

### 残りの4要素

* **Authenticity（真正性）**
  利用者や情報が本物であること。
  例：本人認証

* **Accountability（責任追跡性）**
  誰が何をしたか追跡できること。
  例：操作ログ

* **Non-repudiation（否認防止）**
  自分の行為を後から否定できないようにすること。
  例：デジタル署名

* **Reliability（信頼性）**
  システムが意図したとおりに動作すること。

### 公開鍵暗号とデジタル署名

### 公開鍵暗号

相手だけが読めるように暗号化する方式。

* 暗号化：**相手の公開鍵**
* 復号：**相手の秘密鍵**

目的：機密性の確保。

### デジタル署名

送信者が本人であることと、データが改ざんされていないことを確認する技術。

* 署名：**自分の秘密鍵**
* 検証：**送信者の公開鍵**

目的：真正性・完全性・否認防止。

覚え方：

**暗号化は相手の公開鍵、署名は自分の秘密鍵。**

### 共通鍵暗号と公開鍵暗号の鍵の本数

### 共通鍵暗号

暗号化と復号に同じ鍵を使用する方式。

n人が全員と1対1で安全に通信する場合、

`必要な鍵の本数 = n(n - 1) / 2`

例：4人なら、

`4 × 3 / 2 = 6本`

### 公開鍵暗号

公開鍵と秘密鍵のペアを使用する方式。

n人がそれぞれ鍵ペアを持つ場合、

`必要な鍵の本数 = 2n`

例：4人なら、

`4 × 2 = 8本`

※公開鍵4本、秘密鍵4本。

覚え方：

**共通鍵は相手との組合せごとに必要。公開鍵暗号は1人2本。**

### RSA暗号と楕円曲線暗号
- **RSA（Rivest・Shamir・Adlemanの3名に由来）**：整数の**素因数分解の困難さ**に基づく公開鍵暗号方式。暗号化・電子署名に利用。
- **ECC = Elliptic Curve Cryptography（楕円曲線暗号）**：楕円曲線上の**離散対数問題の困難さ**に基づく暗号技術。鍵共有・電子署名などに利用。
- **覚え方**：**RSA＝素因数分解、楕円曲線＝短い鍵で高い安全性を実現しやすい**。
- **例**：おおむね同程度の128ビット安全性なら、RSA 3072ビットと楕円曲線暗号256ビットが目安。

### 耐タンパ性
Tamper Resistance = 改ざん・解析への耐性。  
機器やデータを不正に読み取ったり、改ざんしたりすることを困難にする性質。  
読み取ろうとすると故障したり、データを消したりする。

### リスクアセスメント

リスクを発見し、その危険度を調べ、対応の必要性を判断すること。

次の3段階で行う。

1. **リスク特定**
   どのような危険が存在するか洗い出す。

2. **リスク分析**
   発生確率や影響度から、危険の大きさを調べる。

3. **リスク評価**
   リスクを許容できるか、対応が必要か判断する。

### 重要

**リスクアセスメントには、対策の実施は含まれない。**

対策を選択・実施するのはリスク対応。

### リスク対応の4種類

* **リスク回避**
  リスクを生む行為そのものをやめる。
  例：危険なサービスを廃止する。

* **リスク低減**
  発生確率や被害を小さくする。
  例：多要素認証を導入する。

* **リスク移転・共有**
  損失の負担などを他者と分担する。
  例：サイバー保険に加入する。

* **リスク保有・受容**
  リスクを理解したうえで受け入れる。
  例：軽微な損失は自社で負担する。

覚え方：

**回避＝やめる
低減＝減らす
移転＝分担する
保有＝受け入れる**

### Webアプリケーションへの攻撃と対策

### SQLインジェクション

SQL = Structured Query Language（構造化照会言語）

不正なSQLを送り込み、データベースを不正操作する攻撃。

対策：

* プレースホルダ（パラメータ化クエリ）
* データベースの権限を最小限にする

**最重要：プレースホルダ**

### XSS

XSS = Cross-Site Scripting（クロスサイトスクリプティング）

Webページに悪意のあるスクリプトを埋め込み、利用者のブラウザで実行させる攻撃。

対策：

* 出力時の適切なエスケープ
* CSP（Content Security Policy：コンテンツセキュリティポリシー）の設定

**最重要：出力時のエスケープ**

### CSRF

CSRF = Cross-Site Request Forgery（クロスサイトリクエストフォージェリ）

ログイン中の利用者に、意図しない操作を実行させる攻撃。

例：ログイン中の銀行サイトに対して、不正な送金要求を送信する。

対策：

* CSRFトークン
* CookieのSameSite属性
* 重要操作時の再認証

**最重要：CSRFトークン**

### OSコマンドインジェクション

OS = Operating System（オペレーティングシステム）

不正な入力によって、サーバ上でOSコマンドを実行させる攻撃。

対策：

* 外部入力をシェルのコマンド文字列に埋め込まない
* シェルを経由しない安全なAPIを使用する

API = Application Programming Interface（ソフトウェア間の機能呼出しなどを行う仕組み）

### ディレクトリトラバーサル

`../`などを悪用して、本来アクセスできないファイルにアクセスする攻撃。

例：

```text
正常：
/images/photo.jpg

攻撃：
/images/../../etc/passwd
```

対策：

* 利用者にファイルパスを直接指定させない
* ファイルIDからサーバ側で保存先を決定する
* 正規化後のパスが許可領域内か確認する

### クリックジャッキング

透明な画面などを重ね、利用者に意図しないクリックをさせる攻撃。

対策：

* `X-Frame-Options`
* CSPの`frame-ancestors`

これらで、外部サイトからの不正な埋め込みを制限する。

### 攻撃と対策の暗記

* SQLインジェクション → **プレースホルダ**
* XSS → **出力時エスケープ**
* CSRF → **CSRFトークン**
* OSコマンドインジェクション → **シェル経由の実行を避ける**
* ディレクトリトラバーサル → **パス指定を制限**
* クリックジャッキング → **iframeなどへの埋め込みを制限**

### パスワードを狙う攻撃

### ブルートフォース攻撃

考えられるパスワードを総当たりする攻撃。

対策：試行回数制限、多要素認証。

### 辞書攻撃

よく使われる単語やパスワードを試す攻撃。

対策：長く推測困難なパスワード。

### パスワードリスト攻撃

他サービスから流出したIDとパスワードを使ってログインを試す攻撃。

対策：パスワードの使い回しをやめる、多要素認証。

### パスワードスプレー攻撃

少数のよく使われるパスワードを、多数のアカウントに対して試す攻撃。

対策：多要素認証、異常な認証試行の検知。

### レインボーテーブル攻撃

事前に計算したハッシュ値の一覧を使い、パスワードを推測する攻撃。

対策：ソルト、適切なパスワードハッシュ方式。

### ソルトとストレッチング

### ソルト

パスワードに利用者ごとのランダム値を加えてからハッシュ化する技術。

目的：

* 同じパスワードでも異なるハッシュ値にする
* レインボーテーブル攻撃を困難にする

### ストレッチング

パスワードのハッシュ計算を意図的に重くする技術。

目的：

* パスワードの大量推測を遅くする

覚え方：

**ソルト＝ハッシュ値を個別化する
ストレッチング＝計算を遅くする**

※実際の実装ではArgon2idなどのパスワード専用ハッシュ方式を利用する。

### コードサイニング証明書

Code Signing = コード署名。

プログラムの発行元と、改ざんされていないことを確認するための電子署名に使用する証明書。

例：ダウンロードしたアプリが、正当な開発元によって署名されているか確認する。

**署名が正しくても、プログラム自体の安全性が保証されるわけではない。**

### CRLとOCSP

### CRL

Certificate Revocation List（証明書失効リスト）

有効期限前に失効した電子証明書を一覧にしたもの。

### OCSP

Online Certificate Status Protocol（オンライン証明書状態確認プロトコル）

電子証明書の失効状態をオンラインで個別に問い合わせる方式。

覚え方：

**CRL＝失効リストを見る
OCSP＝オンラインで問い合わせる**

### リスクベース認証

アクセスの危険度に応じて認証の厳しさを変更する方式。

例：

* 普段の端末からログイン → 通常の認証
* 普段と異なる国からログイン → 追加認証

目的：安全性と利便性の両立。

### 3Dセキュア2.0

EMV 3-D Secure。

インターネット上のクレジットカード決済で、カード利用者本人か確認する仕組み。

* 取引情報などから不正利用リスクを評価
* 低リスクなら追加操作なしで認証できる場合がある
* 高リスクなら追加認証を要求する

リスクベース認証の考え方を利用している。

### SAML

SAML = Security Assertion Markup Language（セキュリティ表明マークアップ言語）

異なるサービス間で認証結果を安全に連携するための規格。

主にSSOに利用される。

SSO = Single Sign-On（シングルサインオン）

一度の認証で複数のサービスを利用する仕組み。

### 関連用語

* IdP = Identity Provider（認証情報を提供する側）
* SP = Service Provider（サービスを提供する側）

例：会社のアカウントで認証すると、複数の業務システムを利用できる。

### ファイアウォールとWAF

### ファイアウォール

Firewall = 防火壁。

IPアドレスやポート番号などを使い、通信を許可・拒否する仕組み。

主にネットワーク間の通信を制御する。

### WAF

WAF = Web Application Firewall（Webアプリケーションファイアウォール）

Web通信の内容を検査し、Webアプリケーションへの攻撃を検知・遮断する仕組み。

例：

* SQLインジェクション
* XSS

覚え方：

**ファイアウォール＝通信の入口を守る
WAF＝Web通信の中身を調べる**

### DMZ

DMZ = Demilitarized Zone（非武装地帯）

インターネットと社内ネットワークの間に設ける、外部公開サーバ用の独立したネットワーク領域。

```text
インターネット
      │
[ファイアウォール]
      │
     DMZ
      │
  Webサーバ
  メールサーバ
      │
[ファイアウォール]
      │
社内ネットワーク
      │
  社内PC
  社内データベース
```

目的：

**外部公開サーバが攻撃されても、社内ネットワークへの侵入を防ぎやすくする。**

### TLS・IPsec・L2TP・SSH

### TLS

Transport Layer Security（トランスポート層セキュリティ）

通信を暗号化し、改ざん検知や相手の認証などを行う技術。

例：HTTPS

HTTPS = Hypertext Transfer Protocol Secure（暗号化されたWeb通信）

### IPsec

Internet Protocol Security（IPセキュリティ）

IP層で通信を暗号化・認証する技術群。

例：拠点間VPN。

VPN = Virtual Private Network（仮想専用ネットワーク）

### L2TP

Layer 2 Tunneling Protocol（レイヤ2トンネリングプロトコル）

通信をカプセル化してトンネルを作る技術。トンネル＝仮想的な通信経路、ただ暗号化はされてない。

**L2TP自体には暗号化機能がない。**

そのため、IPsecと組み合わせることがある。

### SSH

Secure Shell（セキュアシェル）

暗号化された通信で、コンピュータを安全に遠隔操作する技術。

例：Linuxサーバのリモート管理。

覚え方：

**TLS＝Web通信などを保護
IPsec＝IP通信を保護
L2TP＝トンネルを作る
SSH＝安全な遠隔操作**

### メールを守る技術

### SPF

Sender Policy Framework（送信者ポリシーの枠組み）

送信元IPアドレスが、そのドメインからのメール送信を許可されているか確認する。

**SPF＝送信元IPアドレス**

### DKIM

DomainKeys Identified Mail（ドメイン鍵によるメール認証）

電子署名を利用して、送信ドメインの認証とメールの改ざん検知を行う。

**DKIM＝電子署名**

### DMARC

Domain-based Message Authentication, Reporting and Conformance（ドメインベースのメール認証・報告・適合）

SPF・DKIMの認証結果と、差出人ドメインとの整合性に基づいて、メールの取扱方針を示す仕組み。

例：

* 受信する
* 迷惑メールとして隔離する
* 拒否する

**DMARC＝なりすましメールへの対応方針**

### S/MIME

Secure/Multipurpose Internet Mail Extensions（安全な多目的インターネットメール拡張）

電子メールの暗号化と電子署名を行う規格。

**S/MIME＝メール本文の暗号化・電子署名**

### 覚え方

* SPF → IPアドレス
* DKIM → 電子署名
* DMARC → 認証結果に基づく方針
* S/MIME → 本文の暗号化・電子署名

### 脆弱性を見つける技術

### ファジング

Fuzzing

大量の異常なデータやランダムなデータを入力し、プログラムの不具合を発見する方法。

例：不正な形式のファイルを大量に読み込ませ、異常終了しないか調べる。

### ペネトレーションテスト

Penetration Test（侵入試験）

攻撃者の立場から、実際にシステムへ侵入できるか検証するテスト。

### ポートスキャン

Port Scan

サーバのポートを調査し、通信を受け付けているポートを確認する方法。

### デジタルフォレンジック

Digital Forensics（デジタル鑑識）

コンピュータやログなどを調査し、インシデントの原因や証拠を明らかにする技術。

例：不正アクセス後にログを解析し、侵入経路を調査する。

※主目的は脆弱性発見ではなく、証拠保全・原因究明。

### CSIRT・PSIRT・SOC

### CSIRT

Computer Security Incident Response Team（コンピュータセキュリティインシデント対応チーム）

組織で発生したセキュリティインシデントに対応するチーム。

例：社内で情報漏えいが発生した際の調査・対応。

### PSIRT

Product Security Incident Response Team（製品セキュリティインシデント対応チーム）

自社製品の脆弱性やセキュリティ問題に対応するチーム。

例：販売した製品に脆弱性が発見され、修正対応を行う。

### SOC

Security Operations Center（セキュリティ運用センター）

ネットワークやシステムを監視し、攻撃や異常を検知・分析する組織。

覚え方：

**SOC＝監視・検知
CSIRT＝組織の事故対応
PSIRT＝製品のセキュリティ対応**

### CVE・CVSS・SBOM

### CVE

Common Vulnerabilities and Exposures（共通脆弱性識別子）

公開された脆弱性を識別するための番号。

例：`CVE-2024-12345`

**CVE＝脆弱性の番号**

### CVSS

Common Vulnerability Scoring System（共通脆弱性評価システム）

脆弱性の深刻度を数値で評価する仕組み。

例：深刻度を0.0〜10.0で評価する。

**CVSS＝脆弱性の深刻度**

### SBOM

Software Bill of Materials（ソフトウェア部品表）

ソフトウェアに含まれるライブラリや依存関係などを一覧にしたもの。

目的：脆弱性を含む部品が使われていないか確認しやすくする。

**SBOM＝ソフトウェアの部品表**

### セキュリティクリアランス

機密情報を取り扱う人物について、適性を審査する制度。

例：国家安全保障に関わる機密情報を扱える人物か調査する。

重要：

**適性が認められても、業務上必要な情報だけにアクセスできる。**

これをNeed to Know（知る必要性）の原則という。

### WORM・ランサムウェア対策
- **WORM = Write Once Read Many（一度書込み・何度も読取り）**：一度記録したデータを、定められた保持期間中は変更・削除できないようにする方式。
- **ランサムウェア**：データの暗号化や窃取などを行い、身代金を要求する不正プログラム。
- **対策**：WORMなどの改ざん困難なバックアップ、オフライン保管、アクセス権の最小化、更新・多要素認証、復元テスト。
- **覚え方**：**WORM＝「書いたら固定」**。バックアップは「取る」だけでなく、**攻撃から守り、戻せること**が重要。
- **例**：バックアップをWORMストレージに保管し、感染しても過去の正常データを復元する。


### ハッシュ関数とHMAC
- **意味**：ハッシュ関数は入力から固定長のダイジェストを生成。**HMAC = Hash-based Message Authentication Code**は秘密鍵を用いて改ざんと送信元の正当性を検証する方式。
- **覚え方**：**ハッシュ＝指紋、HMAC＝秘密の合言葉付き指紋**。
- **例**：APIのメッセージ認証にHMACを使用する。


### ゼロトラスト
- **意味**：社内・社外を問わず接続元を無条件に信頼せず、アクセスごとに認証・認可などで検証する考え方。
- **覚え方**：**社内だから安全、とは決めつけない**。
- **例**：社内ネットワークでも端末状態と利用者IDを確認してアクセス制御する。

### IDS・IPS・EDR
- **意味**：**IDS = Intrusion Detection System**は侵入検知、**IPS = Intrusion Prevention System**は侵入防御、**EDR = Endpoint Detection and Response**は端末での検知・対応。
- **覚え方**：**IDS＝知らせる、IPS＝止める、EDR＝端末で調べて対処**。
- **例**：ネットワークの異常はIDS/IPS、PC上の不審な挙動はEDRで調査。

### SIEMとSOAR
- **意味**：**SIEM = Security Information and Event Management**はログの集約・相関分析、**SOAR = Security Orchestration, Automation and Response**は対応手順の連携・自動化。
- **覚え方**：**SIEM＝分析する、SOAR＝対応を回す**。
- **例**：複数ログをSIEMで分析し、不審端末の隔離をSOARで自動化する。

### OAuth 2.0とOpenID Connect
- **意味**：**OAuth 2.0**は主に権限委譲の枠組み、**OpenID Connect（OIDC）**はOAuth 2.0を基盤とする認証の仕組み。
- **覚え方**：**OAuth＝何をしてよいか、OIDC＝誰なのか**。
- **例**：別アプリへ写真閲覧の権限を渡すのはOAuth、外部IDでログインするのはOIDC。

### 認証の3要素と多要素認証
- **意味**：知識（パスワード）・所持（トークン）・生体（指紋）を別の要素として組み合わせる。
- **覚え方**：**知っている／持っている／体そのもの**。
- **例**：パスワード＋認証アプリは多要素、パスワード＋秘密の質問は同じ知識要素。

### ディフィー・ヘルマン鍵共有
- **意味**：**DH = Diffie–Hellman**。通信相手と共通の秘密を、秘密そのものを送らずに合意する仕組み。
- **覚え方**：**鍵を送らず、鍵を共有する**。
- **例**：TLSなどで利用される一時鍵共有（ECDHEなど）につながる。

## 07. ソフトウェア設計・開発・テスト

**既存ノートから整理した項目**

### プロファイラ
プログラムの実行時間や関数の呼出し回数などを測定し、処理が遅い場所を調べるためのツール。  
→ ボトルネックの発見に使う。

### ヒューリスティック評価
Heuristic Evaluation  
専門家が経験則やユーザビリティの原則に基づいて、画面やシステムの使いやすさを評価する方法。

### 思考発話法
利用者にシステムを操作してもらいながら、考えていることを声に出してもらう評価方法。

→ 利用者がどこで迷っているのかを発見できる。

### カルーセル
複数の項目を横方向などに並べ、スライドさせながら切り替えて表示するUI。

### モジュール結合度

モジュール同士の依存関係の強さを表す指標。

**結合度は弱いほど、一般的に保守や変更が容易になる。**

### 弱い順（良い → 悪い）

1. **データ結合**
   必要なデータだけを引数で渡す。

2. **スタンプ結合**
   構造体などをまとめて渡す。

3. **制御結合**
   処理方法を指示する情報を引数で渡す。

4. **外部結合**
   外部で定義されたデータや仕様に依存する。

5. **共通結合**
   複数モジュールが共通の大域データを共有する。

6. **内容結合**
   他モジュールの内部を直接参照・操作する。

### 覚え方

**デ → ス → 制 → 外 → 共 → 内**

最も良い：データ結合
最も悪い：内容結合

### リグレッションテスト

Regression Test（回帰テスト）

プログラムを修正した結果、以前正常だった機能が壊れていないか確認するテスト。

例：

ログイン機能を修正した後、会員登録やログアウトも正常に動作するか確認する。

### 残存バグ数の推定計算

複数の独立したテストで見つかったバグの重複から、全体のバグ数を推定する方法。

### 計算方法

* テストAで発見：a件
* テストBで発見：b件
* 両方で発見：c件

推定総バグ数：

`a × b / c`

発見済みの異なるバグ数：

`a + b - c`

推定残存バグ数：

`a × b / c - (a + b - c)`

### 例

* A：10件
* B：8件
* 共通：4件

推定総バグ数：

`10 × 8 / 4 = 20件`

発見済み：

`10 + 8 - 4 = 14件`

残存バグ数：

`20 - 14 = 6件`

→ **残り6件と推定できる。**

※テスト間の独立性などを仮定した推定方法。

### 信頼度成長曲線

テストの進行に伴う、累積発見バグ数などの変化を示す曲線。

* 横軸：テスト時間・作業量
* 縦軸：累積発見バグ数など

典型的にはS字型になる。

### S字型になる理由

1. 初期：テストが進まず、バグ発見が少ない
2. 中期：テストが進み、バグを多く発見する
3. 後期：修正が進み、新しいバグの発見が減る

覚え方：

**後半で曲線が水平に近づくと、バグの発見数が減っている。**

※バグが完全になくなったことを意味するわけではない。

### レビューの種類

### ウォークスルー

Walkthrough

作成者が設計書やプログラムを説明し、参加者が問題点を指摘するレビュー。

特徴：**作成者中心**

### インスペクション

Inspection

役割や手順を定め、体系的に欠陥を発見するレビュー。

特徴：**形式的・組織的**

覚え方：

**ウォークスルー＝作成者が説明
インスペクション＝決められた手順で検査**

### ソフトウェア保守の4種類

### 是正保守

発見された不具合を修正する。

例：プログラムのバグを修正する。

### 適応保守

環境の変化に対応する。

例：新しいOSに対応させる。

### 完全化保守

性能・機能・使いやすさなどを改善する。

例：処理速度を改善する。

### 予防保守

将来の不具合や障害を防ぐために改善する。

例：不具合を起こしやすいコードを事前に修正する。

覚え方：

**是正＝直す
適応＝環境に合わせる
完全化＝より良くする
予防＝将来の不具合を防ぐ**

### Webアプリ
- **PWA = Progressive Web App**：Webアプリをネイティブアプリっぽく使える。オフライン動作など。
- **SPA = Single Page Application**：ページ全体を再読込せず、必要な部分だけ書き換える。
- **WebSocket**：サーバとブラウザで双方向通信を継続する。
- **OpenAPI**：Web APIの仕様を記述する形式。

### 品質管理
- **パレート図**：原因を件数の多い順に並べ、優先して改善する項目を探す。
- **特性要因図**：結果と原因の関係を魚の骨のように整理する。


### モジュール凝集度
- **意味**：1つのモジュール内の機能がどれだけ強く関連しているか。一般に**凝集度は高いほど望ましい**。
- **覚え方**：**結合度は低く、凝集度は高く**。
- **例**：認証機能だけをまとめたモジュールは、無関係な処理を混ぜたものより凝集度が高い。

### 循環的複雑度（サイクロマティック複雑度）
- **意味**：プログラムの分岐などで増える、独立した実行経路の数を表す指標。
- **覚え方**：**分岐が増えるほどテストが難しくなる**。
- **例**：単純な条件分岐1つで、一般的な数え方では複雑度が1増える。

### 同値分割と境界値分析
- **意味**：同値分割＝同じ扱いになる入力をグループ化。境界値分析＝区切りの前後を重点的に試す。
- **覚え方**：**代表を試す／境目を試す**。
- **例**：1～100が有効なら、代表値50のほか0・1・100・101を確認。

### 命令網羅・分岐網羅・条件網羅
- **意味**：**C0（命令網羅）**＝各命令を実行、**C1（分岐網羅）**＝各分岐結果を通す、**C2（条件網羅）**＝各単純条件の真偽を通す。
- **覚え方**：**C0＝行、C1＝道、C2＝条件の真偽**。
- **例**：`if (A && B)`の条件網羅はAとBそれぞれの真・偽を確認する。

### 単体・結合・システム・受入テスト
- **意味**：単体＝部品、結合＝部品のつながり、システム＝全体、受入＝利用者の要求に合うかを確認。
- **覚え方**：**部品 → 接続 → 全体 → 利用者の確認**。
- **例**：関数テスト→API連携→業務シナリオ→顧客による受入判定。


### CI・CD
- **意味**：**CI = Continuous Integration（継続的インテグレーション）**＝変更を頻繁に統合して自動ビルド・テスト。**CD**は継続的デリバリー／継続的デプロイを表す。
- **覚え方**：**CI＝統合して検査、CD＝届ける・配備する**。
- **例**：Gitへのpushを契機にテストを実行し、合格後に配布できる状態を作る。

### テストダブル（スタブ・ドライバ・モック）
- **意味**：スタブ＝呼び出される側の代役、ドライバ＝呼び出す側の代役、モック＝呼出しなどの振る舞いを検証する代役。
- **覚え方**：**スタブ＝下から支える、ドライバ＝上から呼ぶ**。
- **例**：DB未完成時に仮の応答を返すスタブを利用する。

### オブジェクト指向の3要素
- **意味**：カプセル化＝内部を隠してまとめる、継承＝性質を引き継ぐ、ポリモーフィズム（多態性）＝同じ操作でも対象で動作が変わる。
- **覚え方**：**隠す／引き継ぐ／同じ呼出しで違う動き**。
- **例**：`Animal`型の`鳴く()`を呼ぶと犬と猫で動作が異なる。

## 08. アジャイル開発・プロジェクト管理

**既存ノートから整理した項目**

### プロジェクトとプログラム
プロジェクト = 1つの仕事を成功させる  
プログラム = 複数プロジェクトをまとめて、全体として価値を出す  

### EVM
Earned Value Management  
PV: 予定出来高、EV: Earned Value: 実際の出来高、AC: かかったコスト
<img width="422" height="233" alt="image" src="https://github.com/user-attachments/assets/9e359076-4a54-4548-9b47-b17293d02cee" />

PV > AC > EVなら、予定より遅れて、コストもかかっている。コストは、現在のEVに対して高い（上にある）。

### アジャイル開発宣言の4つの価値

アジャイル開発は、変化に対応しながら小さく作り、改善を繰り返す開発の考え方。

### 4つの価値

1. **プロセスやツールよりも、個人と対話**
2. **包括的なドキュメントよりも、動くソフトウェア**
3. **契約交渉よりも、顧客との協調**
4. **計画に従うことよりも、変化への対応**

重要：

**右側にも価値はあるが、左側をより重視する。**

### スクラムの3つの役割

### プロダクトオーナー

Product Owner

プロダクトの価値を最大化する責任を持つ。

主な役割：

* プロダクトの方向性を明確にする
* プロダクトバックログを管理する
* 開発項目の優先順位を決める

**何を優先して作るかを決める人。**

### スクラムマスター

Scrum Master

スクラムが適切に機能するように支援する人。

主な役割：

* スクラムの理解と実践を支援する
* チームが抱える障害の解消を促す
* チームの改善を支援する

**スクラムを円滑に進めるための支援役。**

### 開発者

Developers

スプリントごとに利用可能な成果物を作る責任を持つ。

主な役割：

* 開発作業の計画
* 設計・実装・テスト
* 品質の確保

**実際に製品を作る人たち。**

### スプリント

Sprint

1か月以内の一定期間で、利用可能な成果物を作る開発サイクル。

### スプリントの流れ

```text
プロダクトバックログ
        ↓
スプリントプランニング
        ↓
スプリント開始
        ↓
開発・テスト
   （デイリースクラム）
        ↓
スプリントレビュー
        ↓
スプリントレトロスペクティブ
        ↓
次のスプリント
```

### スプリントプランニング

今回のスプリントで何を達成するか、どのように進めるか計画する。

### デイリースクラム

開発者が毎日15分以内で進捗を確認し、作業計画を調整する。

### スプリントレビュー

完成した成果物を関係者と確認し、今後の方向性を調整する。

### スプリントレトロスペクティブ

チームの進め方を振り返り、改善策を考える。

覚え方：

**計画 → 開発 → 成果確認 → 振り返り → 次へ**

### スプリントのKPT
- **KPT = Keep・Problem・Try**：スプリントの振り返りなどで使う改善整理法。
  - **Keep**：良かったので続けること。
  - **Problem**：問題・困ったこと。
  - **Try**：次に試す改善策。
- **覚え方**：**続ける・困った・次に試す**。
- **例**：Keep＝毎朝の進捗共有、Problem＝レビュー待ちが多い、Try＝レビュー担当を早めに決める。
- ※KPTは振り返りに使える**手法の一つ**で、スクラムで必須の形式ではない。

### プロダクトバックログとスプリントバックログ

### プロダクトバックログ

プロダクトに必要な機能や改善項目を、優先順位付きで整理したリスト。

管理責任：プロダクトオーナー。

### スプリントバックログ

今回のスプリントで実施する作業と、その実施計画などをまとめたもの。

管理：開発者。

### インクリメント

Increment

完成の定義を満たした、利用可能なプロダクトの成果物。

覚え方：

**プロダクトバックログ＝製品全体でやりたいこと
スプリントバックログ＝今回やること
インクリメント＝完成した成果物**

### プロジェクトマネジメント
- **プロジェクト憲章**：プロジェクトを正式に開始・承認する文書。
- **スコープ**：何をやるか・何をやらないかの範囲。
- **WBS = Work Breakdown Structure**：作業を階層的に細分化する。
- **PMBOK = Project Management Body of Knowledge**：プロジェクト管理の知識体系。

### スケジュール短縮
- **クラッシング**：人・設備などを追加して短縮。→ コスト増。
- **ファストトラッキング**：本来順番に行う作業を並行化。→ 手戻りリスク増。
- **CCPM = Critical Chain Project Management**：各作業の余裕をまとめてバッファとして管理。資源制約も考える。

### その他
- **コンティンジェンシー計画**：想定されるリスクが実際に起きた場合の対応計画。
- **インシデント管理**：障害発生後、できるだけ早くサービスを正常に戻す。
- **問題管理**：インシデントの根本原因を分析し、再発防止につなげる。



### PERTの3点見積り
- **意味**：**PERT = Program Evaluation and Review Technique**。期待時間は`(楽観値+4×最頻値+悲観値)/6`。
- **覚え方**：**いちばんありそうな時間を4倍重視**。
- **例**：楽観2日、最頻5日、悲観8日→`(2+4×5+8)/6=5日`。

### RACIチャート
- **意味**：役割を**Responsible（実行責任）・Accountable（最終責任）・Consulted（相談先）・Informed（報告先）**に整理。
- **覚え方**：**やる人／最終責任者／相談相手／知らせる相手**。
- **例**：機能リリースで開発担当R、責任者A、法務C、営業Iを設定する。

### EVMのCPI・SPI
- **意味**：**CPI = Cost Performance Index（コスト効率指数）＝EV/AC**、**SPI = Schedule Performance Index（スケジュール効率指数）＝EV/PV**。
- **覚え方**：**CPI＝実績価値÷使った費用、SPI＝実績価値÷予定価値**。どちらも1未満は悪い方向。
- **例**：EV80、AC100、PV100ならCPI＝0.8、SPI＝0.8。

### ベロシティとバーンダウンチャート
- **意味**：ベロシティ＝スプリントで完了した作業量の実績。バーンダウン＝残作業量の推移を表示。
- **覚え方**：**ベロシティ＝進む速さ、バーンダウン＝残りが減る図**。
- **例**：スプリント終了時に完了したストーリーポイントを次回の計画に活用。

## 09. ITサービスマネジメント・監査・事業継続

**既存ノートから整理した項目**

### 監査
監査＝ミスのあら捜しではない。適切に、効率的に行われているかのチェック

### インシデントと問題の違い
- インシデント：実際に起きた障害、不具合
- 問題：インシデントを引き起こしている原因

### 事業継続
- **RTO = Recovery Time Objective（目標復旧時間）**：何時間以内に復旧するか。
- **RPO = Recovery Point Objective（目標復旧時点）**：どの時点のデータまで戻せればよいか。
- **RLO = Recovery Level Objective（目標復旧レベル）**：どの程度の機能・サービスまで復旧するか。
- **MTRS = Mean Time to Restore Service（平均サービス回復時間）**：サービス復旧までの平均時間。短いほどよい。
- **FTA = Fault Tree Analysis（故障の木解析）**：結果から原因を木構造でたどる。確率も見れる


### SLAとSLM
- **意味**：**SLA = Service Level Agreement（サービスレベル合意）**＝サービス品質の約束、**SLM = Service Level Management（サービスレベル管理）**＝品質を測定・改善する活動。
- **覚え方**：**SLA＝約束、SLM＝約束を守る管理**。
- **例**：月間稼働率99.9%をSLAで定め、実測値を定期確認する。

### SLIとSLO
- **意味**：**SLI = Service Level Indicator（サービスレベル指標）**＝測定値、**SLO = Service Level Objective（サービスレベル目標）**＝目標値。
- **覚え方**：**I＝Indicator（ものさし）、O＝Objective（目標）**。
- **例**：SLIが可用性99.95%、SLOが99.9%以上なら目標達成。

### MTBF・MTTRと稼働率
- **意味**：**MTBF = Mean Time Between Failures（平均故障間隔）**、**MTTR = Mean Time To Repair（平均修理時間）**。修復可能な系の単純モデルでは稼働率＝`MTBF/(MTBF+MTTR)`。
- **覚え方**：**MTBFは長いほど良い、MTTRは短いほど良い**。
- **例**：MTBF90時間、MTTR10時間なら稼働率90%。

### BIA（事業影響度分析）
- **意味**：**BIA = Business Impact Analysis**。業務停止が事業に与える影響を調べ、復旧の優先度を決める。
- **覚え方**：**止まると困る仕事を先に洗い出す**。
- **例**：決済業務の停止は影響が大きいため、早期復旧対象とする。


### 内部統制と職務分掌
- **意味**：内部統制＝業務の適切性を確保する仕組み。職務分掌＝承認・実行・記録などの権限を分け、不正や誤りを防ぐ。
- **覚え方**：**1人に全部任せず、牽制が働く仕組み**。
- **例**：経費の申請者と承認者を別の人にする。

## 10. 経営戦略・IT戦略・ビジネスモデル

**既存ノートから整理した項目**

### コアコンピタンス
自社独自の強み

### ストラテジ
- **EA = Enterprise Architecture**：会社全体の業務とITを整理し、全体最適する。
- **SOA = Service-Oriented Architecture**：機能を独立したサービスに分けて組み合わせる。
- **BPR = Business Process Re-engineering**：業務プロセスを根本から作り直す。
- **BPO = Business Process Outsourcing**：業務を外部企業へ委託する。
- **ERP = Enterprise Resource Planning**：会計・人事・販売・生産などの基幹業務を統合管理する。
- **SFA = Sales Force Automation**：顧客・商談・営業活動を管理する営業支援システム。

### 経営分析
- **SWOT**：Strength（強み）、Weakness（弱み）、Opportunity（機会）、Threat（脅威）。
- **PEST**：Political（政治）、Economic（経済）、Social（社会）、Technological（技術）。
- **3C**：Customer（顧客）、Competitor（競合）、Company（自社）。
- **ファイブフォース**：新規参入・代替品・買い手・売り手・既存競合の5つで業界の競争を分析。

### PPM
**PPM = Product Portfolio Management**  
市場成長率 × 相対的市場占有率で事業を分類する。

- 花形：成長率高・占有率高
- 問題児：成長率高・占有率低
- 金のなる木：成長率低・占有率高
- 負け犬：成長率低・占有率低

### アンゾフの成長マトリクス
製品 × 市場を、既存・新規で分類する。

- 既存製品 × 既存市場：市場浸透
- 新規製品 × 既存市場：新製品開発
- 既存製品 × 新規市場：新市場開拓
- 新規製品 × 新規市場：多角化

### バランススコアカード（BSC）
- **BSC = Balanced Scorecard**：経営戦略の達成状況を**財務・顧客・内部ビジネスプロセス・学習と成長**の4視点から管理する。
- **覚え方**：**人が育つ → 仕事が良くなる → 客が喜ぶ → 儲かる**。
- **例**：社員研修（学習と成長）→不良率低下（内部）→満足度上昇（顧客）→利益増加（財務）。

### ポートフォリオ
- **ポートフォリオ**：複数の資産・事業・投資・プロジェクトなどを、**全体として見た組合せ・構成**。
- **ポートフォリオマネジメント**：組合せ全体を評価し、予算・人員などの配分を考えること。
- **覚え方**：**手持ちのカードの組合せと、そのバランス**。
- **例**：IT投資を「新規AI開発60%・セキュリティ30%・業務改善10%」に配分する。

### バックキャスティング
- **バックキャスティング（Backcasting）**：まず**望ましい未来の目標**を決め、実現のために今何をするか**逆算**する計画手法。
- **覚え方**：**未来から現在へ逆算**。フォーキャスティング（Forecasting）は、現状から未来を予測。
- **例**：「2030年にCO₂排出量を半減」から逆算し、2028年・2027年の施策を決める。

### アグリゲーションサービス
- **アグリゲーション（Aggregation：集約）**：分散している情報やサービスをまとめ、ひとつの窓口から利用できるようにするサービス。
- **覚え方**：**バラバラなものを1か所に集める**。
- **例**：複数の銀行口座やクレジットカードの利用状況を、家計簿アプリでまとめて確認する。

### オムニチャネル
- **オムニチャネル（Omnichannel）**：実店舗・ECサイト・アプリなど**複数の顧客接点を連携**し、一貫した購買体験を提供する考え方。
- **覚え方**：**どの窓口でも、つながった買い物体験**（アグリゲーションは「集約」、オムニチャネルは「連携」）。
- **例**：スマホで注文し、店舗で受け取り、購入履歴やポイントも共通化する。


### KGI・KPI・CSF
- **意味**：**KGI = Key Goal Indicator（重要目標達成指標）**、**KPI = Key Performance Indicator（重要業績評価指標）**、**CSF = Critical Success Factor（重要成功要因）**。
- **覚え方**：**KGI＝最終ゴール、CSF＝成功のカギ、KPI＝途中の数値**。
- **例**：KGI＝売上1億円、CSF＝顧客定着、KPI＝継続購入率60%。

### VRIO分析
- **意味**：**Value（価値）・Rarity（希少性）・Imitability（模倣困難性）・Organization（組織体制）**で経営資源の競争優位を評価。
- **覚え方**：**価値があり、珍しく、真似されず、活かせるか**。
- **例**：独自技術があっても社内体制が整わなければ強みを十分活用できない。

### バリューチェーン
- **意味**：企業活動を購買・製造・物流・販売・サービスなどの連鎖として捉え、どこで価値が生まれるか分析。
- **覚え方**：**材料から顧客に届くまでの価値の鎖**。
- **例**：物流を改善して納期を短縮し、競争力を高める。

### ブルーオーシャン戦略
- **意味**：競争が激しい既存市場で戦うより、新しい価値を作って競争の少ない市場を開拓する戦略。
- **覚え方**：**レッド＝血みどろの競争、ブルー＝競争の少ない海**。
- **例**：既存商品の値下げ競争ではなく、新しい利用体験を提供する。

### CRMとSFAの違い
- **意味**：**CRM = Customer Relationship Management（顧客関係管理）**は顧客との長期関係、**SFA = Sales Force Automation（営業支援）**は営業活動の効率化を重視。
- **覚え方**：**CRM＝お客さんとの関係、SFA＝営業担当の仕事**。
- **例**：顧客の問い合わせ履歴管理はCRM、商談進捗管理はSFA。

### DXとデジタル化
- **意味**：**DX = Digital Transformation**はデジタル技術で事業・組織・価値提供を変革すること。単なる紙の電子化より広い。
- **覚え方**：**デジタル化＝道具を変える、DX＝ビジネスを変える**。
- **例**：紙の申請書をPDF化＝デジタル化、申請業務そのものを再設計＝DX。

## 11. マーケティング・財務・生産・組織

**既存ノートから整理した項目**

### 投資の評価
- **ROI = Return on Investment**：利益 ÷ 投資額。
- **PBP = Payback Period**：投資額を何年で回収できるか。
- **NPV = Net Present Value（正味現在価値）**：将来のお金を現在価値に直して投資額と比較。正なら投資価値あり。
- **IRR = Internal Rate of Return（内部収益率）**：NPVが0になる割引率。

### マーケティング
- **ターゲットリターン価格設定**：目標利益率を達成できるよう価格を決める。
- **プライスライニング**：複数の価格帯を設定して商品をそろえる。
- **フリーミアム**：基本無料、高度な機能は有料。
- **バイラルマーケティング**：口コミやSNSで人から人へ情報を広げる。
- **ROAS = Return On Advertising Spend**：広告経由売上 ÷ 広告費 × 100%。

### 損益計算
- **利益 = 売上 - 固定費 - 変動費**
- **固定費**：売上量に関係なく発生する費用。
- **変動費**：販売量に応じて増減する費用。
- **変動費率 = 変動費 / 売上**
- **限界利益率 = 1- 変動費率**
- **損益分岐点売り上げ= 固定費 / 限界利益率**
- **損益分岐点**：利益が0になる売上。
- 損益分岐点が低いほど、少ない売上で黒字化できる。

### 生産・技術
- **エネルギーハーベスティング**：光・熱・振動などの微小エネルギーを電力に変える。
- **マスカスタマイゼーション**：大量生産の効率を保ちながら顧客ごとにカスタマイズする。
- **ファブレス**：自社工場を持たず、半導体の設計を中心に行う企業。
- **ファウンドリ**：他社が設計した半導体を製造する企業。
- **EMS = Electronics Manufacturing Services**：他社ブランドの電子機器を製造受託する。

### 意思決定・組織
- **SL理論 = Situational Leadership Theory**：部下の成熟度に合わせてリーダーシップを変える。
- **マクシミン原理**：各案の最悪値（min）を取り、その中で最大（max）の案を選ぶ。
- **ナッシュ均衡**：相手の戦略を前提にすると、誰も自分だけ戦略を変えて得をしない状態。


### 損益分岐点売上高の式
- **意味**：損益分岐点売上高＝`固定費/(1-変動費率)`。変動費率＝変動費÷売上高。
- **覚え方**：**固定費を、売上から変動費を引いた割合で回収する**。
- **例**：固定費300万円、変動費率40%なら`300/(1-0.4)=500万円`。

### ROEとROA
- **意味**：**ROE = Return on Equity（自己資本利益率）＝当期純利益÷自己資本**、**ROA = Return on Assets（総資産利益率）**は総資産に対する利益の割合（利益の定義は問題の指定に従う）。
- **覚え方**：**E＝Equity（自己資本）、A＝Assets（総資産）**。
- **例**：純利益100万円、自己資本1,000万円ならROE10%。


### EOQ（経済的発注量）
- **意味**：**EOQ = Economic Order Quantity**。発注費用と在庫保管費用の合計が最小となる発注量。
- **覚え方**：**少しずつ発注＝注文が多い、大量発注＝在庫が多い、その中間が最適**。
- **例**：毎週少量発注する場合と年1回大量発注する場合の費用を比較する。


### JITとカンバン方式
- **意味**：**JIT = Just In Time**は必要なものを必要なときに必要な量だけ供給する考え方。カンバンは後工程の引取りに基づく生産指示の方法。
- **覚え方**：**JIT＝必要なときだけ、カンバン＝後工程から知らせる**。
- **例**：組立工程（後工程）が消費した部品数に応じて前工程へ補充を依頼する。

## 12. 法務・知的財産・ライセンス

**既存ノートから整理した項目**

### 著作権
- 著作物の権利は原則として**著作者**に発生する。
- 委託して作ってもらった成果物の著作権を委託元へ移したい場合は、**著作権譲渡を契約で定める**。
- **著作者人格権は譲渡できない**ため、必要に応じて「著作者人格権を行使しない」という不行使特約を定める。
- 著作者人格権には、公表権・氏名表示権・同一性保持権などがある。

※会社員が職務として作成したプログラムなどは、一定条件で会社が著作者になる「職務著作」もあるため、「必ず作った個人が著作権者」とは限らない。

### 特許・実施許諾
- **特許権**：特許発明を業として独占的に実施できる権利。**特許の設定登録で発生**する（出願しただけでは発生しない）。
- **実施**：特許発明の内容に応じ、製造・使用・販売・輸入などを行うこと。
- **実施許諾（ライセンス）**：特許権者が、他者にその発明の実施を認めること。
- **通常実施権**：許諾された範囲で実施できるが、原則として**独占ではない**。複数社への許諾も可能。
- **専用実施権**：**設定登録が必要**。設定された範囲では実施権者が独占し、**特許権者自身も実施できない**。
- **存続期間**：原則として**出願日から20年**（例外あり）。
- **覚え方**：**通常＝複数社OK、専用＝その範囲を独占**。
- **例**：A社の特許技術についてB社・C社の双方に許諾するのは通常実施権。B社だけが一定範囲で独占するのが専用実施権。

### 法律
- **特定電子メール法**：広告メールは原則、事前同意した人に送る。
  - **オプトイン**：事前に同意してもらう。
  - **オプトアウト**：今後の受信を拒否する。
- **刑法**：犯罪と刑罰を定める基本的な法律。ITではウイルス作成・提供や電子計算機損壊等業務妨害など。
- **労働者派遣**：派遣先が労働者へ直接指揮命令する。
- **請負**：発注者は請負会社の労働者へ直接指揮命令しない。直接指示すると偽装請負になる可能性。
- **PL法 = Product Liability Law（製造物責任法）**：製造物の欠陥によって生じた損害について製造業者などが責任を負う。ソフトウェア単体は原則対象外。

### GPL
GPL = GNU General Public License  
強いコピーレフト型ライセンス。  
GPLのプログラムを改変・組込みして派生物を配布する場合、原則として派生物にもGPLを適用し、対応するソースコードを提供する必要がある。

### BSDライセンス
BSD = Berkeley Software Distribution  
制約が比較的少ないライセンス。  
著作権表示などの条件を守れば、改変・再配布・商用利用が可能。  
派生物を同じライセンスで公開する義務は基本的にない。

### MITライセンス
MIT = Massachusetts Institute of Technology  
非常に制約が少ないライセンス。  
著作権表示とライセンス表示を残せば、改変・再配布・商用利用などが可能。

### Apache License
Apache License 2.0  
比較的自由なライセンス。  
MITやBSDと似ているが、特許に関する許諾が明示されているのが特徴。



### 特許・実用新案・意匠・商標の違い
- **意味**：特許＝技術的な発明、実用新案＝物品の形状・構造等の考案、意匠＝デザイン、商標＝商品・サービスの目印。
- **覚え方**：**技術／小さな工夫／見た目／ブランド**。
- **例**：新しい充電方式＝特許、ケース構造の工夫＝実用新案、外観＝意匠、ロゴ＝商標。


### 中小受託取引適正化法（取適法）
- **意味**：旧「下請法」を改めた法律。**2026年1月1日施行**。適用対象の委託取引で代金支払遅延や不当な減額などを防ぐ。
- **覚え方**：**受託する中小事業者を、不公正な取引から守る**。
- **例**：発注側が合意なく代金を一方的に減らす行為は問題になり得る。
- **試験メモ**：応用情報シラバスVer.7.2では旧「下請法」表記から変更された。

### 請負契約と準委任契約
- **意味**：**請負**は仕事の完成が契約の中心、**準委任**は法律行為以外の事務処理の遂行が中心（特約などで具体的な責任は異なる）。
- **覚え方**：**請負＝完成を約束、準委任＝業務の遂行を約束**。
- **例**：完成品を納入する開発契約は請負、一定期間の運用支援は準委任が候補。

### 特許の先願主義
- **意味**：同一の発明について、原則として**先に出願した者**が特許を受けられる仕組み。先に思いついただけでは優先されない。
- **覚え方**：**発明の順番より、出願の順番**。
- **例**：同じ発明をA社が先に出願し、B社が後から出願した場合、原則A社が優先。

## 最後の復習チェック（短時間で差がつく項目）

特に選択肢の取り違えが起きやすい対比です。**左側だけ見て、右側を説明できるか**確かめてください。

| 覚える対比 | 正しく区別するポイント |
|---|---|
| デッドロック ↔ 排他制御 | 循環待ちの発生 ↔ 同時アクセスを防ぐ制御 |
| フェールセーフ ↔ フェールソフト | 安全側にする ↔ 機能を落として継続 |
| NAT ↔ NAPT | IPアドレス変換 ↔ IP＋ポート変換 |
| ARP ↔ DNS | IPv4→MAC（同一リンク上） ↔ ドメイン名→IPなど |
| ACID ↔ BASE | トランザクションの性質 ↔ 分散DBで可用性・結果整合性等を重視する考え方 |
| 適合率 ↔ 再現率 | 陽性判定の正しさ ↔ 真の陽性の拾い上げ |
| GRANT ↔ REVOKE | 権限を付与 ↔ 権限を取消し |
| C0 ↔ C1 ↔ C2 | 命令網羅 ↔ 分岐網羅 ↔ 条件網羅 |
| KGI ↔ KPI ↔ CSF | 最終目標の指標 ↔ 途中の管理指標 ↔ 成功の重要要因 |
| 請負 ↔ 準委任 | 完成が中心 ↔ 業務遂行が中心 |
| 特許 ↔ 意匠 ↔ 商標 | 発明 ↔ デザイン ↔ ブランドの目印 |

**注記**：原文の記述は原則維持しています。難度の高い例外・制度改正は公式資料で再確認してください。
